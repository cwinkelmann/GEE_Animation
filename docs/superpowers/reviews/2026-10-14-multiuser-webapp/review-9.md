## Findings

1. CRITICAL - cross-user / arbitrary server-file read via `aoi_path` (app.py, ServerContext.submit, the `aoi_src` block). `aoi_path` comes from the client's Gradio FileData payload. Gradio only checks the extension (.geojson/.json/.zip), not that the path is inside its upload cache. Probe: user A posted `{"path": "<user C's run dir>/secret.geojson"}` to `/gradio_api/call/_go`. `submit` copied the file into A's own `aoi/` dir and put it in the worker payload (content "OTHER-USERS-FILE" readable there). The copy deviation makes this worse: it launders the foreign file into A's own, servable tree. User AOI copies are exactly `.geojson`/`.zip` files, and any `.json` on the box (e.g. ~/.config/earthengine/credentials) qualifies. Fix: in `submit`, resolve `aoi_path` and require it to lie under the Gradio upload cache (`tempfile.gettempdir()/gradio`) or the staged-preset/bundled-AOI dir; reject otherwise. Add a test that submits a path in another user's dir and expects refusal.
2. IMPORTANT - spawn.py `run`: `async for line in proc.stdout` uses asyncio's default 64 KiB line limit. Confirmed: a >64 KiB line raises `ValueError` ("chunk is longer than limit"). The worker's `done` event carries the whole `frames` path list; ~600+ frames (e.g. a daily cadence over several years, allowed by caps) overflows it. The exception propagates, JobQueue reports "The render failed to start." for a render that succeeded. Fix: `create_subprocess_exec(..., limit=...)` large (e.g. 16 MiB) or have the worker emit only a count/zip. The stray-stdout test cannot catch this.
3. IMPORTANT - no test covers per-user scoping of `ServerContext.list_runs` (nor `user_of` returning None for stale sid). `test_the_run_list_is_empty_for_an_anonymous_request` only calls `oauth.current_user(SimpleNamespace(cookies={}))`; it never touches app.py and passes whatever app.py does (vacuous; this is the brief's own test but it was kept). Mutation "list_runs ignores email / lists everything" fails no test. Add: two sessions, two seeded runs, assert each `list_runs` sees only its own, anonymous sees [].
4. IMPORTANT - `test_the_upload_limit_is_set...` asserts only `app.state.max_upload_bytes`. Dropping `max_file_size=` from `mount_gradio_app` leaves it green. Enforcement does work (I probed: 2 MB upload against a 1 MB cap returns 413), so add that probe as the test.
5. MINOR - app.py `lifespan`/`logsafe.install`: root-logger install covers only records logged on root or reaching root's handlers. Root has no handlers under uvicorn, so child-logger records (gradio, authlib, google.auth, httpx) go to `logging.lastResort`, which carries no filter (reasoned, not probed). The uvicorn loggers (the main carriers) are covered and ordering is correct: uvicorn configures logging before lifespan runs. Defence in depth only; the web process never puts a refresh token in an exception message.
6. MINOR - spawn.py:`create_subprocess_exec` passes no `env`: the worker inherits GEE_OAUTH_CLIENT_SECRET and GEE_COOKIE_SECRET. No refresh token travels in env (verified: argv is only `-m gee_animation.webapp.worker`; token goes via stdin only). Pass a minimal env. Worker stderr is inherited (unredacted by the server's filter); the worker catches and scrubs exceptions, but library stderr goes straight to the container log.
7. MINOR - spawn.py `kill()` uses `proc.kill()` (one pid) although the comment says `start_new_session` makes the kill "clean"; ffmpeg children survive a timeout. Use `os.killpg`.
8. MINOR - `submit`: run dir `f"{sensor}_{index}_{stamp}"` has 1 s resolution and the unsanitised sensor/index. Two clicks in one second (concurrency_limit=None allows it) share a directory. Gradio's Dropdown validation blocks `../` today, but `submit` is the trust boundary and caps.check does not validate them. Add a uuid suffix and sanitise.
9. MINOR - `run_coroutine_threadsafe(...).result()` has no timeout. The hand-off itself is correct (coroutine runs on the captured loop; `create_task` happens inside the loop; probed end to end with a real `gr.Request`). If the loop is gone the Gradio thread hangs.
10. MINOR - sweep runs only at startup, so the 14-day retention is enforced only on restart (matches the brief; mention in deploy notes). Finished `Job`/`WorkerProcess` objects keep the refresh token in `_payload` in memory after the session is dropped, and the redactor then no longer knows it (memory only; allowed by the credential rule).
11. MINOR - `GEE_FORWARDED_ALLOW_IPS` default trusts all of 10.0.0.0/8; carrot and likely the VPN clients live there. Tighten in deploy once the Caddy address is known. `project.validate` (Task 7) is never called in the web path and worker.py's comment says the project is "validated at login": a bad project costs a queue slot instead of failing fast.
