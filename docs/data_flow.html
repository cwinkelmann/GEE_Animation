gee_animation · pipeline

From satellite passes to an
annotated NDVI timelapse

A config-driven pipeline. Each module has one job and takes Earth Engine as an injected dependency. Data flows top‑to‑bottom — a config.yaml in, an MP4 + GIF + per-month PNGs out.

config.pyRunConfig.from_yaml()

Read & validate the run

Dates, AOI, sensor, index, cloud thresholds, viz range and screen preset are parsed and checked — pure, no network. Bad input fails here, before any EE call.

produces → RunConfig
auth.pyinit(project)

Authenticate Earth Engine

ee.Initialize against project hnee-331218; prompts ee.Authenticate() and retries once on failure.

produces → live EE session
aoi.pyparse() · frame_bbox

Build the geometry

A bbox, GeoJSON, or shapefile becomes an ee.Geometry. The region is the area of interest; a buffered frame box is what actually gets rendered around it.

produces → region geom · frame geom
collection.pybuild(cfg, geom)

Filter & cloud-mask the archive

Pulls Sentinel-2 (or Landsat), keeps scenes overlapping the frame in the date range, drops cloudy scenes via the SCL/QA mask and the AOI cloud threshold, then adds the index band — e.g. NDVI = (B8−B4)/(B8+B4).

produces → ImageCollection (masked, +index)
compositing.pymonthly_median()

Collapse each month to one median frame

Scenes are tagged with their YYYY-MM and counted. For every month, all of that month's cloud-filtered scenes are stacked and reduced pixel-wise with .median() into a single Frame(label, image, n_scenes). Empty months are skipped; min_scenes gates thin months.

6?

Yes — n = 6 means six source scenes were combined into that month's composite, not one image shown six times.

The subtlety: n counts scenes overlapping the month. Each output pixel is the median of only its cloud-free observations, so a heavily-clouded pixel may draw on fewer than 6 values — and where zero clear values remain, that pixel is the AOI cloud fraction recorded downstream.

produces → list[Frame] — one per non-empty month
render.pyrender(frames, geom)

Style every frame & encode

Per frame: fetch the thumbnail at native resolution → colorize with a fixed palette and range (comparable across the animation) → paint no-data pixels neutral grey → draw month label, colorbar and amber region outline → Lanczos-upscale to the screen preset → write PNG. Frames assemble to MP4 + GIF.

produces → out/<name>/…mp4 · .gif · _YYYY-MM.png
metadata.pywrite_frame_metadata()

Log per-frame cloud metadata

For each frame, measures the share of the AOI with no cloud-free value — aoi_cloud_fraction = 1 − clear — and stores it with n_scenes in a SQLite frame_clouds table. Cloud is measured inside the AOI, not over the whole scene.

produces → out/<name>/metadata.db
n_scenes
Scenes stacked into the month's median. Higher = more chances to see through clouds.
median (not mean)
Robust to outliers — a bright cloud or dark shadow in one scene is outvoted rather than averaged in.
fixed viz range
Same min/max + palette every frame, so colour means the same thing all animation long.
injected EE
Every module takes ee_module as a dependency — testable with no network.
